## What changes

The simulator carries forward #119's existing loopback-only CLI containment,
confirmed-response checks, expected-command binding and synthetic lifecycle
guards. The scripted demonstration refuses a mismatched pending command before
acknowledging it or inventing execution/management receipts. Rejected or malformed
responses stop the demonstration instead of producing a successful completion.
Polling can itself claim a command; a mismatch is not permission to repoll,
drain the queue or resend an ambiguous operation.

The performance ledger carries forward #122's existing distinction between a
reported TP/SL milestone and a verified return for the whole trade. It retains
the milestone but withholds scalar realised R when aggregate broker fill/close
evidence is absent. The ledger module's explanatory docstring is aligned with
that behavior; this wording adjustment changes no runtime logic.

`backend/tests/test_simulator.py` combines both existing source hunks: #119's
TP1-only stop-out fixture and #122's strict null-R/unverified-note assertions.
The historical test function name is preserved.

The newer #172 stage-regression test had two assertions demanding an unverified
`6.5R`. After #122 was applied, its first assertion correctly failed because the
ledger returned `None`. Both assertions now require `None`. All command-stage,
ledger-status, audit, notification, distinct-receipt and idempotency checks remain.
The current #172 `crud.py`, command routes, auth, models and schema are unchanged.
