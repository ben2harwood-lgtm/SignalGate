# SignalGate Provider Edition — Commercial Offer

## What the provider buys

SignalGate Provider Edition is controlled execution infrastructure for a signal provider's own signals, customers and brand.

The current commercial path is:

**Provider signal -> deterministic validation -> subscriber consent/authorisation -> tenant-bound command -> demo execution -> broker reconciliation -> evidence ledger.**

SignalGate does not sell proprietary signals or promise trading returns.

## Recommended initial product

### Controlled Provider Pilot

Use a time-boxed demo-account pilot before any broader deployment.

Included:

- one provider organisation;
- one or more configured feeds;
- provider portal access;
- subscriber consent invites;
- feed symbol/expiry/lot policy;
- provider/feed pause controls;
- provider credential issuance/rotation;
- demo-account EA/simulator onboarding;
- execution/reconciliation history;
- incident/support channel;
- pilot evidence report.

Excluded unless separately agreed:

- real-money retail execution;
- automated copy trading without per-transaction user action;
- bespoke broker adapters;
- custom SSO/RBAC;
- guaranteed performance or profitability;
- regulated advice/signals;
- 24/7 managed operations.

## Pricing structure

Price the service as infrastructure, not as a percentage of trading gains.

Recommended quotation components:

1. **Onboarding/integration fee** — provider setup, feed configuration, test scenarios and implementation support.
2. **Recurring platform fee** — access to Provider Edition and standard operations.
3. **Usage band** — active connected accounts and/or execution volume.
4. **Optional services** — white-labelling, custom integration, extended support, dedicated environment, additional broker adapters.

Do not publish a permanent price card until beta establishes onboarding effort, support hours, infrastructure cost and willingness to pay. Preserve every quote and accepted price point as pricing evidence.

## Sales proof

A provider-facing demonstration should prove:

- tenant isolation;
- provider-specific credentials;
- subscriber consent;
- deterministic rejection of unsafe/ambiguous signals;
- pause/kill paths;
- duplicate/retry protection;
- demo execution and stopped-out loss evidence;
- broker reconciliation;
- audit/history;
- encrypted recovery baseline.

Do not use unverified demand, Nick-specific claims or invented profitability.

## Contract pack needed before paid beta

Counsel-reviewed versions of:

- provider/pilot order form;
- master/service terms;
- data/privacy schedule;
- acceptable-use rules;
- support/service schedule;
- regulatory responsibility allocation;
- subprocessor/privacy notices where applicable.

Repository drafts/checklists are operational preparation, not substitutes for counsel.

## Expansion after pilot

Move from controlled pilot to wider provider use only after the beta acceptance gates are met and operating evidence shows the support/reliability model is sustainable.

Enterprise/broker expansion can then add SSO/RBAC, API/SDK/embed, dedicated environments, broader adapter coverage and contractual SLOs.
